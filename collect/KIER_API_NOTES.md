# KIER Open API 4종 호출 메모

공공데이터포털 KIER API 4종의 호출 방법과 확인된 제약입니다(2026-10-23 시험 호출 기준). 인증키는 `.env`의 `DATAGO_KEY`(4개 서비스 공통 1개)에서만 읽으며 코드·로그·화면에 쓰지 않습니다.

```
GET https://apis.data.go.kr/B551184/<서비스>/<오퍼레이션>?serviceKey=<키>&date=YYYYMMDD&lat=&lon=&pageNo=&numOfRows=&type=json
```

## 핵심 주의

- 위경도는 **문자열 앞부분(prefix) 일치** 필터입니다. 좌표는 반올림하지 말고 API가 돌려준 문자열(또는 그 앞부분)을 씁니다.
- 일일 호출 한도 10,000건. 약 25회/초(4스레드)에서 HTTP 429가 나므로 호출 간 0.12초 이상 + 429 대기 재시도를 씁니다(`collect/_kapi.py`).
- 풍력은 `totalCount`가 매우 커서(588,120) 필터 동작 확인 전 대량 수집을 하지 않습니다.

## 시험 호출 요약 (각 1회, lat=37.5 lon=127.0 numOfRows=3)

- 4종 모두 HTTP 200, `resultCode=00 NORMAL_SERVICE` → 키 유효
- 태양에너지: date=20210601 → totalCount 5,070
- 풍력: date=20220601 → totalCount 588,120
- 발전량 예측·실시간 일사량은 처음에 0건이었고, 원인은 날짜 범위와 좌표 형식(위 표)이었습니다.

## 수집 설계 참고

- 발전량 예측은 태양에너지(solar_api)와 같은 165칸을 재사용할 수 있습니다(칸당 1호출/일).
- 실시간 일사량은 날짜 범위를 먼저 확인합니다. 조회 가능 날짜가 최근일에서 끊기는 이유는 확인하지 못했습니다.
